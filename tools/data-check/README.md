# Scenario data check

`validate_scenario.py` checks the story in `docs/designathon/05-scenario-data.md` against the competition data. It reads the scenario's machine-readable appendix (the fenced `relay:` blocks) and recomputes each fact from the CSVs in `data/raw/data`. That covers vehicle and outlet attributes, store names (district, and Kandy city areas close to Kandy Town), calendar flags, order numbers and sizes, and every Wednesday trip. For each trip it checks one district and brand, the temperature rule, van-only access and capacity. It also checks the organizers' trip-time standard, imported from `data/raw/check_allocation.py`, against the 270 and 480 minute budgets, the two-trip limit, a clock for second trips, and weekly fuel. On top of that it re-runs the exact searches behind the deferral, the paper plan, the Monday and Thursday checks (including VEH039's second Thursday trip) and the 33-day capacity outlook. It tests Kasun's times against the route history, checks that he touches his phone only while stopped, and checks that each estimate range contains the actual arrival and never starts before the time shown. It recomputes the story-board statistics, including the five-vehicle Wednesdays and the Matale departures in the history. Finally it checks that every number the text prints appears in it word for word, that the timeline table matches its appendix block, that wording found wrong in review stays out, and that there is no em dash, en dash or arrow. The shared model is in `relay_model.py`; the printed strings are rebuilt in `printed.py`.

Run it from anywhere with Python 3.11, pandas, numpy and scipy: `python tools/data-check/validate_scenario.py`. A full run takes about six minutes, because it re-solves the outlook for 33 days and the five-vehicle case for each Wednesday ahead. `--quick` skips those searches, and `-v` lists every passing check. It prints a line per section and a final `PASSED n checks` line, and exits with code 1 on any failure. The data stays in `data/raw/`; anything a script derives goes in `data/derived/`, which git ignores. When you change a string in a Figma step file or a spec, change the same fact in the scenario and its appendix, then run the validator.
