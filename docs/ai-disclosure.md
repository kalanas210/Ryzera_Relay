# AI tool disclosure: Hackathon

Relay's Hackathon build was written largely by Claude (Anthropic, Opus 5.5) in Claude Code on Kalana's PC, directed by Kalana in chat. Much of it ran as multi-agent workflows: builders on separate files, reviewer agents that had not written the code, verifiers that reproduced each finding before anything was fixed, and an integrator that ran every check before a commit. Claude also wrote the commit messages and made the commits, all under Kalana's GitHub account (`kalanas210`) with no AI co-author line, so `git log` shows what was built and when, and this page says who did it. The running record is [`ai-usage-log.md`](ai-usage-log.md); the Designathon's own disclosure is kept at the tag `designathon-submission`, in `docs/designathon/07-ai-disclosure.md`.

## How the output was checked

- **Automated.** `pytest` runs the engine tests (the booklet's own trip-time examples, the eleven rules, and the story day's proposal of 56 of 57 Kandy hub orders on 18 trips) and the API tests, which create, migrate and seed a throwaway PostgreSQL database and drive private copies of the day through the API. Vitest runs the web app's unit tests. Playwright walks the README's judge walkthrough and the offline driver in Chromium, each test in a private copy of its own. GitHub Actions runs these, with Ruff, mypy, Biome, the TypeScript check, the production build and `docker compose build`, on every push to `main`, and runs the browser tests against `docker compose up` (`.github/workflows/ci.yml`).
- **Agents.** Reviewers and checkers that had not written the code read it against the specs and used the running app in a browser, on private copies of the day, at phone and tablet sizes.
- **People.** _To fill by the team._ Until this is filled in, no human review of the code is claimed.

## Data

- Claude read the organizers' datasets (kept out of git in `data/raw/`) and wrote `seed/scripts/build_story.py`, which writes the committed seed: copies of the organizers' reference tables the seed needs (`seed/data/reference/`, beside our store names), tables derived from the history (usual runs and stops, unloading times, order patterns, the capacity outlook) and the story day.
- The story's orders for 8 and 9 April 2026 are not in the datasets. Their sizes come from the forecast in `tools/data-check/relay_model.py`, which Claude wrote during the Designathon: the Kandy hub's orders as printed in the scenario appendix of `docs/design/05-scenario-data.md`, and every other order sized the same way.
- Invented for the story: the people and their names (most drivers' names are generated from lists of first names and surnames), the store names (real towns in each outlet's district, since the data has none), the receivers' names, the plan change notes, the dispatcher's on-call number, the story times, and the drawn stand-in photo and signature the autopilot records. The Designathon persona portraits were generated with Canva AI; the app does not use them.

## No AI inside Relay

No AI model runs in the product. The code and its dependencies call no model API: a search of the repository and its dependency lists for OpenAI, Anthropic, Gemini and similar SDKs and keys found none on 2 October 2026. The planning engine is an exact optimiser, not a learned model: integer programs solved with HiGHS through SciPy, under eleven written rules. Estimates during a silent run follow one written rule (`packages/engine/src/relay_engine/estimate.py`). The story autopilot and the world simulator are scripts that play fixed story steps and schedules.
